An SDLC instrument for humans and AI agents building together

Tiller

  • Tillerholds the structure, the gates, and the state.
  • The agentdoes the reasoning and the work.
  • Youapprove at the gates.
  • Your mergeis the only thing that makes work done.

Everything lives in the repo: markdown for prose, YAML for state, git as the spine. Written against v0.21.2; when this page and the binary disagree, the binary wins.

The passage

One tree of work: epics hold features, features hold tasks, each level elaborated just in time. Every feature sails the same route, and the three magenta gates are yours. Magenta on this page means exactly one thing: a human is needed.

You
The agent

You · Onboard

Scaffold the workspace, record who you are, drop the design inputs in.

tiller init · tiller join --as <you>

Agent · Orient

Reads the state, names the seam, briefs you, and stops. The stop is your briefing moment: standing context goes to AGENTS.md.

tiller guide

Agent · Decompose

Lays the whole epic and feature tree down in draft, records dependencies and open questions, commits the diff, and stops.

tiller add epic · add feature · link --depends-on · add question
Gate 1 · The tree You review the committed diff and approve the shape of the work. tiller approve epic <epic>

Agent · Specify (per feature, just in time)

Writes the specification (feature.md), the acceptance contract (feature.eval.md), and the task explosion (tasks/<key>/task.md), then asserts the whole stage. Spec checks what was written; it writes nothing.

tiller spec feature <feature>

draft → specced: inked, awaiting your signature.

Gate 2 · The plan You read the spec and contract; one approval moves the feature and its initial tasks to ready, basis pinned. tiller approve feature <feature>

Agent · Execute (per task)

Starts the feature and its first task, codes on the recorded branch, runs the gates (build, tests, the acceptance contract), and submits the PR.

tiller start · check · submit --pr <n>

active → in_review: driven to the edge of done.

You · Attest along the way

Manual criteria and review gates are your judgment, recorded as yours. The agent hands you the command; it never runs it.

tiller attest <node> --criterion C-x --status pass
Gate 3 · The merge You review the PR and merge it, in git or on the host. Tiller never merges; an agent never marks done.

Either · Sync

Observes the merge and records the crossing: the task is done by evidence, and the feature and epic roll up behind their tasks. Nothing is ever marked done by hand.

tiller sync

↓ back to the frontier: the next feature's specify turn, in dependency order.
Alongside the loop: the question ledger (add question · answer question), the drift sweep (tiller drift), and your read-only console (tiller serve).

A feature's states draft specced ready active in_review done and the exception: blocked

Who runs what

The gate is your decision, not necessarily your keyboard. Full syntax for every command lives in tiller-commands.md.

You, delegable

The agent may type these only on your explicit instruction naming the nodes, and says what it will record first.

approvereturncancelarchive

Approving is the review. approve --refresh-basis re-records a drifted basis; approve --reviewed-assumption clears an answered question.

You alone, never delegable

Human judgment, recorded as such. The agent hands you the command and stops.

attestanswer questionsync --accept-fast-forwardthe merge

The merge is git's, not Tiller's, and it is the one boundary that physically holds.

The agent's lane

Its day job. You can run any of these yourself; the agent runs them for you.

addlinkspecstartcheck submitresumeevalsyncguidereadout

Laying the tree, writing and asserting specs, driving tasks to review, running gates, observing merges.

Either: setup and reads

Setup once, reads always.

initjoinstatusshowls treesearchdriftserve

serve exists for your eyes; drift is a read that names what moved out of agreement.

These lanes are guidance the agent is asked to honor, not walls: Tiller guides, it does not control, and every action attributes to the person who directed it. The enforcement that genuinely holds sits at the merge.

What you say to the agent

The eleven skills installed by tiller join (among them /tiller-orient, /tiller-decompose, /tiller-specify, /tiller-execute, and /tiller-mend-drift) mean you steer in plain sentences and the agent finds the commands. The shapes that come up, by moment:

Orienting and briefing

The agent surfaces the picture and stops. The stop is your briefing moment; durable context belongs in AGENTS.md.

  • Orient yourself and tell me where things stand.
  • We work through PRs only; never push to main. Record that in AGENTS.md.
  • Tests run with bin/ci; the design system lives at docs/design-system.md.

Decomposing

The agent proposes; the committed diff is the review surface. The go is a delegated gate, so name the set.

  • Decompose the project from the design docs.
  • Split the reporting epic; it is doing two jobs.
  • Record that as a question blocking the auth feature instead of deciding it now.
  • The tree looks right; approve all nine epics.

Specifying

The agent writes the spec, the contract, and the tasks, then asserts. You read, push back in prose, and take the plan gate.

  • Specify foundation/repo-tooling.
  • Criterion C3 is untestable as written; make it a command binding.
  • Six tasks is too coarse; split the migration work.
  • I have read the spec; approve the feature.

Executing

One task at a time, driven to review on its own branch.

  • Work the next task and drive it to review.
  • Run the gates and show me what is red.
  • Submit it; the PR number is 41.
  • Stop: that approach duplicates the form engine. Rework the task spec.

Questions and assumptions

Open decisions live in the ledger, not in chat. Answering is yours to type.

  • File a question: does a submitted certification form lock after 48 hours? It blocks the certification form loading feature.
  • Proceed under Q-1hxeyk on the assumption the lock is 48 hours; record the assumption.
  • You answer at the keyboard: tiller answer question Q-1hxeyk --answer "..."

The crossings you keep, and drift

At its boundaries the agent hands you commands rather than running them. If it ever offers to merge, that is a briefing bug, not a convenience.

  • I merged the PR; run sync.
  • Run the drift sweep and propose fixes for what moved.
  • Attestation stays at your keyboard: the agent pastes the tiller attest line and waits.
